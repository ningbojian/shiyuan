# 数据说明（DATA）

氏源的数据以仓库内 `data/catalog.json` 为唯一可复现来源。数据库中的姓氏、分布、人物、迁徙与源流记录均可由该文件重建，不需要手工录入。

## 一句话结论

这是**课程展示用的整理数据 + 课程归档原始资料**，不是权威人口统计。33 个整理条目经过结构化整理；315 个导入条目来自课程归档、未做内容校订。页面与接口中的“分布强度”只是可视化示意值，不能当作各省人口占比、排名或学术结论引用。

## 数据规模

| 内容 | 数量 |
|---|---|
| 姓氏 | 348（33 个整理条目 + 315 个课程原始资料条目） |
| 历史人物 | 6,251（整理 132 + 原始 6,212 − 重叠 93） |
| 迁徙事件 | 66（仅整理条目） |
| 源流关系 | 36（仅整理条目，含马→赵、何→韩、叶→沈等跨姓关系） |
| 宗族节点 | 10（姬、嬴、子、妫、姜、祁、曹、妘、己、芈） |
| 省份 | 34（含港澳台） |
| 时期 / 朝代 | 22（夏朝至中华人民共和国） |

33 个整理姓氏为：李、王、张、刘、陈、杨、赵、黄、周、吴、徐、孙、胡、朱、高、林、何、郭、马、罗、梁、宋、郑、谢、韩、唐、冯、于、董、萧、沈、叶、丁。

其中李、王、张、丁四姓的 `base_information`、`fam`、`mig`、`dis`、`ori`、`cul` 六个字段来自 `data/surnames/<姓>/` 下的课程原始文本，按原文完整迁入（`TextField`，不截断）。其余 29 个整理姓氏与所有整理条目的人物、事件、分布、关系文本为演示整理内容。

## 数据从哪来

1. **课程原始样本**：`data/surnames/` 保留李、王、张、丁的原始 `.txt`，是内容来源与回归样本；测试会逐字段比对 catalog 与原文是否一致（空文件除外）。
2. **课程归档（315 个条目）**：上海财经大学《数据库原理》2021 Fall 课程资料目录，共 346 个姓氏文件夹、约 5,037,478 字节。源目录**不随仓库提交**，仓库只保留派生的 `data/catalog.json`。导入条目 `is_imported=True`、`is_demo=True`，显示“课程原始资料 · 未校订”徽章。
3. **整理扩展**：`scripts/generate_catalog.py` 依据姓氏、宗族、地域与人物元数据生成 33 个整理姓氏的摘要、人物、迁徙、分布与关系文本。生成过程是确定性的，重复运行得到相同结果。
4. **参考项目**：`dutongjian.com` / `kxxhhh/Dutongjian` 与知乎项目页只用于借鉴产品结构（目录、人物/地点/事件网络、地图与时间轴、收藏/历史），**没有复制其文本、图片、数据或品牌**。

### 课程归档审计

- 346 个姓氏文件夹，每个最多 6 个文本文件（`基本信息.txt`、`姓氏起源.txt`、`迁徙传播.txt`、`人口分布.txt`、`历代名人.txt`、`姓氏文化.txt`）。
- 完整性并不齐整：`基本信息` 0 缺失、3 空（弓/璩/荀）；`姓氏起源` 2 缺失；`迁徙传播` 51 缺失、2 空；`人口分布` 216 缺失、1 空；`历代名人` 1 缺失（邓）、0 空；`姓氏文化` 2 缺失、2 空。只有 86 个文件夹六项全非空，因此按“部分资料”导入，不假设每姓都有完整六段。
- `rename.xls` 与 `获取文件名.bat` 不导入、不执行。
- `上官` 文件夹的内容实际是**又姓**（人物为又尚珍），导入时按 `上官 → 又` 映射；源数据没有真正的上官资料，目录中不出现“上官”。
- 与 33 个整理姓氏重叠 31 个；`刘`、`叶` 不在源目录；新增 315 个，最终 348 个。重叠姓氏保留整理正文与人物，只追加原始人物中不重名的部分。
- `历代名人.txt` 共 2,583 个朝代标题、6,261 个人物行；8 行姓名或信息为空被跳过，有效 6,253 行；按 `(姓氏, 姓名)` 合并同姓同名（保留最长简介）41 条，得到 6,212 个原始人物；与整理人物重叠 93 人，最终 6,251 人。
- 观测到的 50 种朝代标题全部映射到 22 个标准时期（如 北宋/南宋 → 宋朝，魏/蜀/吴 → 三国）。新增时期：辽朝、金朝、西夏、中华人民共和国。
- 拼音覆盖 9 个确定的多音姓氏：乐→yue、仇→qiu、单→shan、卜→bu、解→xie、翟→zhai、都→du、能→nai、薄→bo；其余保留 pypinyin 默认读音。
- 源文本未发现 HTML/script 标记；解析器仍会检测 `<script`、`onerror=` 等片段并直接失败，不静默清洗。

### 关于分布强度

`Distribution.intensity` 取值范围 0–100，表示“可视化上的相对强度”，不是百分比：

- 同一姓氏的多个省份强度之和可以大于 100；
- 数值由生成脚本按预设序列产生，不代表人口普查数据；
- 每条记录都有 `is_illustrative=True` 与 `source_note`，页面显示“演示数据 · 非权威统计”；
- 315 个课程原始资料条目没有结构化分布数据，只有原文（若有）与“暂无结构化分布数据；以上为原始文字资料”的提示。

### 关于人物与迁徙

整理条目的人物生卒年、朝代与事件描述来自常见历史常识的概述性整理；原始条目的人物直接来自课程归档 `历代名人.txt`，未校订、未解析生卒年。两者都用于演示人物索引、朝代分组与时间轴，不保证完备，也不作为学术引用来源。所有人物记录均带 `source_note`。

```json
{
  "meta": {"version": 2, "generated_at": "2026-10-20", "disclaimer": "..."},
  "clans": [
    {"name": "姬姓", "slug": "ji-xing", "kind": "xing", "description": "..."}
  ],
  "surnames": [
    {
      "second_name": "李",
      "slug": "li",
      "pinyin": "li",
      "initial": "L",
      "aliases": ["李氏"],
      "summary": "60–120 字摘要",
      "base_information": "...",
      "ori": "...",
      "mig": "...",
      "dis": "...",
      "cul": "...",
      "fam": "兼容旧页面的名人长文本（导入条目为空）",
      "keywords": [{"name": "陇西", "value": 40}],
      "source_note": "来源与演示性质说明",
      "is_demo": true,
      "is_imported": false,
      "is_featured": true,
      "popularity": 100,
      "distributions": [
        {"province": "河北省", "intensity": 72, "is_illustrative": true, "source_note": "..."}
      ],
      "figures": [
        {"name": "李白", "slug": "li-bai", "dynasty": "唐朝", "info": "...",
         "birth_year": 701, "death_year": 762, "source_note": "...", "is_demo": true}
      ],
      "migration_events": [
        {"dynasty": "唐朝", "from_province": "河南省", "to_province": "福建省",
         "description": "...", "source_note": "...", "order": 1}
      ],
      "relations": [
        {"target_surname": "赵", "relation_type": "branch",
         "description": "...", "source_note": "..."}
      ]
    }
  ]
}
```

### 字段含义

| 字段 | 含义 |
|---|---|
| `second_name` | 姓氏单字，主键 |
| `slug` | URL 标识（拼音），全站唯一 |
| `pinyin` / `initial` | 拼音与首字母，用于搜索和 A–Z 导航 |
| `aliases` | 别名，逗号分隔存储 |
| `summary` | 列表卡片摘要 |
| `base_information` / `ori` / `mig` / `dis` / `cul` / `fam` | 纯文本资料字段，模板默认转义 |
| `keywords` | 词云数据，`value` 为 1–100 的展示权重；导入条目为空 |
| `source_note` | 该条目的来源与性质说明 |
| `is_demo` | 是否为演示/课程展示内容；导入条目同样为 true |
| `is_imported` | 是否来自课程归档且未校订；为 true 时必须同时 `is_demo=true` 且有 `source_note` |
| `is_featured` / `popularity` | 首页精选与排序权重，由数据显式指定；导入条目为 false / 0 |
| `distribution.intensity` | 0–100 示意强度，非占比 |
| `relation_type` | `origin` 源出 / `branch` 分支 / `changed` 改姓 / `same_clan` 同源 |

关系记录必须恰好指向一个目标：`target_surname`（姓氏）或 `target_clan`（宗族），由数据库 `CheckConstraint` 保证。

## 校验与重新生成

```bash
# 有课程归档时：生成 33 个整理条目 + 315 个原始条目
python scripts/generate_catalog.py \
  --source-dir "<课程归档目录>" \
  --output data/catalog.json

# 没有归档时：只生成 33 个整理条目（不要覆盖完整 catalog）
python scripts/generate_catalog.py

# 校验结构、引用、来源说明、HTML 标记与数量
python manage.py validate_catalog

# 写入数据库（幂等；--dry-run 只看统计）
python manage.py load_catalog

# 开发环境演示数据：省份、朝代元数据、账号、评论、收藏、历史
python manage.py seed_demo
```

### 校验规则（摘要）

- 姓氏数量 ≥ 32（当前 348）；`second_name`、`slug` 唯一。
- `pinyin`、`initial`、`summary`、各资料字段与 `source_note` 非空。
- `is_imported` 必须是布尔值；为 true 时必须同时 `is_demo=true` 且提供 `source_note`。
- `is_demo=true` 的记录必须提供 `source_note`，人物/事件/关系同样适用。
- 省份、朝代、目标姓氏、目标宗族必须存在于允许列表或同一文件。
- `intensity`、`keywords[].value` 为 0–100 / 1–100 的整数。
- 禁止 `<script`、`onerror=`、`javascript:` 等标记片段（纯文本策略）。
- 加载先校验后写入，整体在 `transaction.atomic()` 中执行；默认不删除文件外的既有记录，`--prune` 才清理。

校验失败会列出具体路径（如 `surnames[12].figures[1]: source_note 不能为空`），不会部分写库。

## 修改数据时的约定

1. 优先改 `data/surnames/` 原始文本、课程归档或 `scripts/generate_catalog.py` 中的元数据，再重新生成；不要手改数据库。
2. 33 个整理姓氏的每个条目应保持：60–120 字摘要、8–12 个关键词、6–10 个省份强度、3–5 位整理人物、2–3 条迁徙事件、至少 1 条关系，以及每条记录的 `source_note`。导入条目只要求至少一段原文、非空摘要与来源说明。
3. 不写入 HTML、脚本或外部图片链接；所有内容按纯文本展示。
4. 不引入受版权保护的整段原文；课程归档只在本机用于生成，源目录不提交。
5. 修改后运行 `validate_catalog`、`load_catalog` 与完整测试。

## 已知限制

- 348 个姓氏仍不能代表中国姓氏全貌；
- 315 个条目是未校订的课程资料，可能有错漏、重复或过时表述；31 个重叠姓氏只合并人物，未合并原始正文；
- 原始资料缺章节的情况普遍存在（216 个缺人口分布、51 个缺迁徙传播），页面以空状态和原文区分；
- 人物按 `(姓氏, 姓名)` 合并，同名不同人可能被误合并；未解析生卒年；
- 分布强度只属于 33 个整理条目，是示意值，页面不得将其表述为统计比例；
- 港澳台数据仅作为地图完整性占位，不代表统计口径；
- 未提供数据版本迁移工具；结构变更时重新生成并加载 catalog 即可。
